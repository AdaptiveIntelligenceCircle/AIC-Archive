# Default-deny bridge between parallel nets

**Pre-Covenant · under-claim · not legal advice**

## Metadata

- Date: 2026-10-08
- Related repositories: AIC-Interop, AIC-Formal (Isolation), AIC-TestNet

## Context

Parallel TestNets are useful only if experiments do not silently influence each other.  
An implicit “allow all cross-net traffic” posture would collapse isolation and confuse trust boundaries.

## Decision / statement

Cross-net messages and state effects are **denied by default**.  
Any cross-net effect requires an **explicit ordered grant** `(from_net, to_net)` with `from ≠ to`.  
Grants are directional; `(A,B)` does not imply `(B,A)`.  
Self-grants are disallowed in the sketch.

## Rationale

- Preserves the meaning of “parallel” experimentation.
- Matches fail-closed orientation used elsewhere (Ethical Kernel, recovery sketches).
- Aligns with formal intent (`Inv_DefaultDenyBridge` in AIC-Formal).
- Avoids accidental coupling of phase tracks.

## Alternatives considered

- Default-allow with optional deny lists — rejected (too easy to leave open).
- Bidirectional grants by default — rejected (direction should be explicit).
- Token-weighted bridge rights — rejected (no token rule-power).

## Non-claims

This entry does **not**:

- implement a production bridge
- prove deployment isolation on real networks
- declare Covenant or mainnet readiness
- introduce cryptographic grant authentication (out of scope for the sketch)
